## Set up on a new computer

1. Sign in to OneDrive (Harvard) so the `MAIR Lab Website`, `CV`, `Chief of Staff` and photo folders sync.
   Or clone the repo alone: `gh auth login`, then `gh repo clone willmair/themairlab.com`.
2. Python 3 is all the site needs. For portraits also `pip install pillow numpy` (macOS, uses Apple's
   built-in subject detection; see `scripts/portraits/README.md`).
3. Preview: `python3 -m http.server 8766` in this folder, then open http://localhost:8766.
4. Publish: commit and push to `main`; the site is live in about a minute. Commit identity:
   William Mair <44441828+willmair@users.noreply.github.com>.
5. Recreate the weekly briefing: create a scheduled task (Mondays 7am) whose instructions are the text of
   `OneDrive/Chief of Staff/Weekly briefing setup.md`. Put `Claude global instructions.md` into the new
   assistant's global instructions.

## How the site is built

- Page sources: `pages/*.html` and `pages/people/*.html` (comment block of settings at the top, then the body).
  `python3 scripts/build.py` wraps them in the shared header and footer and writes the root `*.html`,
  `people/*.html`, `sitemap.xml` and `robots.txt`. Never edit the generated files directly.
- Data files in `assets/js/`:
  - `people.js`: current members and alumni (role, years, `now`, `slug`, `photo`, `links`).
  - `news.js`: news and media.
  - `pubs.js`: lab publications, generated by `python3 scripts/update_pubs.py`, which only publishes
    papers whose titles appear in Will's newest CV (other PubMed hits go to `scripts/pending_pubs.json`).
  - `people_pubs.js`: each profile page's publications, generated by `python3 scripts/update_people_pubs.py`
    (run after `update_pubs.py`). Lab papers come from `pubs.js`, matched on full first name in PubMed.
    Other papers come from the person's verified ORCID record, or for people without ORCID from a vetted
    PubMed name search (only CONFIRMED PMIDs show; new hits go to `scripts/pending_people_pubs.json`).
    Current members refresh every run, alumni in the first week of each month (or with `--all`).
- Styles: `assets/css/style.css`. Behavior and renderers: `assets/js/main.js`.
- Profile pages: one per current member and alum in `pages/people/<slug>.html`. Bios use CV facts only.
  Portraits are 4:5 on a shared stone background (`scripts/portraits/`); Scout keeps her own background.

## Rules that matter most (full list in `CLAUDE.md`)

- Accuracy first: only things in Will's CV or his own documents; never another "W. Mair"'s papers; never
  confuse Will with other aging researchers. Name matches for other people are shown only once verified.
- No email addresses on the site; contact goes through the form. No official Harvard giving links.
- US English. No en or em dashes in anything written for Will (site text, documents, chat); use a plain hyphen.
- Never use someone's pronouns unless they have stated them; prefer their name.
- CV edits: archive the current file to `Prior versions` first, never re-add anything Will deleted, edit the
  Word file in place, re-export the PDF, and mirror the change into `cv_data.js` and `last_claude_version.txt`.
- Website changes for Will's review go on a branch; publish to `main` only after he approves.
